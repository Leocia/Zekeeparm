# Zekeeparm 机械臂工作台

复用 [Rebot_Arm_AGV](https://github.com/Yang-Ci/Rebot_Arm_AGV/tree/445b48d5fd9fef8050c8a9ef5fd6ab32e3ace5cf/web_mujoco) 的机械臂网页实现。
机械臂 URDF、STL、预备姿态、碰撞排除和转换器均已收进本项目，可将整个 `web_mujoco/`
复制到其他位置或电脑运行，不需要原 ROS 工作区、ROS 安装或相邻的 `src/` 目录。
上游参考版本为 `445b48d5fd9fef8050c8a9ef5fd6ab32e3ace5cf`。

保留 TCP 拖拽、七个关节/夹爪浮动控制、物体移动与三维旋转、
红/蓝/黄三目标归位、蓝红黄顺序叠放及任务结束回预备位、俯视与 Gemini 305 单路 RGB 预览及布局/折叠/模型开关、
接触力和关节曲线、零件选择/隔离，以及中文、日文、英文切换。
提供 URDF 行号诊断、坐标系与碰撞凸包显示、避障规划轨迹与调试日志；爆炸视图已移除。
界面采用浅色工作台、左侧操作区、中央三维模型、底部相机观察区，并提供仿真暂停。AGV 已移除。

## 启动

需要 Node.js 22+，以及可导入 `mujoco`、`numpy` 的 Python 3。
先按根目录 docs/OPTIONAL_MODULES.md 安装依赖，再运行：

```bash
cd $HOME/Desktop/Zekeeparm/web_mujoco
npm run dev
```

打开 **http://127.0.0.1:5174/**。

新电脑先执行 `npm ci`，并安装 Python 依赖 `python3 -m pip install -r requirements.txt`。
也可先建立 Python 虚拟环境，激活后再执行上述安装及 npm 命令。
`dev`、`build` 和 `test` 会先重新导出当前 URDF，避免继续显示旧模型。
运行时只读取本项目内的模型资源，不再跟随原 ROS 工作区的修改。

```bash
npm test       # TCP 拖拽、物理抓放/避障、规划诊断与距离测量、独立副本构建及同步
npm run build # 生成独立静态网站 dist/
npm run preview
npm run test:static # 真实 Chrome 验证浏览器 URDF 转换和静态站编辑（需 google-chrome 或 CHROME_BIN）
```

构建结果使用相对资源路径，可以放在静态网站的子目录。
WASM 和模型均使用本地资源，网格提供 gzip 版本并保留原文件回退，模型哈希用于更新缓存。

模型资源位置：

| 文件 | 用途 |
| --- | --- |
| `robot/description/urdf/sixaxis.urdf` | 项目内置的默认 URDF |
| `robot/description/meshes/`、`robot/description/collision/` | 内置可视及碰撞网格 |
| `robot/zekeep.srdf` | 预备姿态及碰撞排除 |
| `scripts/urdf_model.py` | 本地 URDF 转换器，保留原控制增益及指垫近似 |
| `simulation.urdf` | 网页编辑后保存的自定义副本，存在时优先使用 |

URDF 中保留 `package://zekeep_bringup/` 资源名，转换器直接将其映射到本项目的 `robot/`，
不会查询 ROS 包。搬移项目时带上整个 `robot/`；需要保留网页修改时也要带上 `simulation.urdf`。

## TCP 拖拽

点击「启用 TCP 拖拽」，拖动末端旁的圆形标记。鼠标或触屏停住但仍按住时，机械臂继续跟随目标。
拖拽循环会保存每一步 IK 的关节结果，避免反复从同一姿态只移动最初几毫米。
仿真暂停时先恢复仿真；TCP 手动拖拽不执行自动避障。

## URDF 编辑与同步

运行 `npm run dev`，在左侧「URDF 同步」展开「编辑 URDF」，修改后点击「保存并同步」。
系统先验证并编译，再保存到本项目的 `simulation.urdf` 并刷新场景；内置默认 URDF 不会被覆盖。
新模型的几何、关节原点/轴/限位、质量/惯量、颜色和速度上限进入仿真；修改后请重新验证任务可达性。
现有指垫保留校准近似，手指网格/碰撞原点、夹爪范围、mimic、dynamics、网格缩放、
几何类型、link/joint 数量及连接关系的更改会被拒绝。关节限位必须包含 SRDF 的 `ready_pose`。
此编辑器适用于当前六轴结构，不是任意机器人导入器。

### 教学诊断与可视化

编辑器停笔 300 ms 后检查 XML、六轴及夹爪关节、父子连接、重复名称、闭环、
关节限位、轴向和质量。诊断列出行号，点击可选中对应源码行。
保存前再次检查；静态站只在浏览器中验证和编译，失败不会替换当前模型。
静态诊断通过不代表模型一定可用，转换器及 MuJoCo 编译器仍会执行完整校验。

「教学实验舱」提供以下视图，均只改变显示：

- **坐标系**：显示各机器人 Link 的当前坐标原点和姿态，X 红、Y 绿、Z 蓝，包含固定连接及夹爪。
- **碰撞包络**：显示 MuJoCo 编译后网格的凸包和实际指垫等碰撞几何，外观半透明。不会修改碰撞掩码或物理参数。
- **轨迹对比**：红色虚线表示被拒的直接 TCP 路线，绿色折线表示通过 IK 和碰撞检查的 TCP 采样轨迹，绿点为过渡航点。
  红标记表示碰撞或安全间距冲突的位置。被拒原因也可能是 IK 或限位，此时不伪造碰撞标记。
  为便于观察，后续无障碍阶段保留最近一次绕行对比；新任务、调整箱体或「清空日志与轨迹」会清除旧图。
- **最近距离**：通过 `mj_geomDistance` 查询当前机器人规划包络与箱体的表面距离及对应端点。
  每 160 ms 更新一次，显示连杆名称和 12 mm 安全阈值。小于阈值时文字及线条报警。

点击「红色搬运场景」会应用示例箱体并启动红色物体归位。日志记录实际目标、6 mm 笛卡尔采样、
0.012 rad 关节边检测、首个失败采样点、IK 或碰撞原因、候选路线和实测规划耗时。
轨迹沿用经过验证的线性关节采样、限速与 PD 跟踪，不将显示曲线平滑成未经碰撞检查的新路径，
也不声称执行了三次多项式或 RRT 规划。日志保留最近 160 条，不向服务器发送。

### 实训操作

1. 展开 URDF 编辑器，把 `joint2` 的 `upper` 改得小于 `lower`，观察精确行号；点击诊断跳转。
   修正为包含 `ready_pose` 的较窄合法范围，保存同步后拖动关节，观察限位与 TCP 可达性。
   开启坐标系和碰撞包络，比较 `<origin>` 修改前后的几何位置。
2. 运行红色搬运场景，观察直线失败、上方或侧向候选以及绿色安全轨迹。
   停止或复位后改变箱体尺寸、位置，再观察路径和日志。
   直接将箱体放入机器人或物体内部仍会被安全校验拒绝，不会为演示关闭校验。
   将箱体放在放置目标附近，可观察候选路线无解时停止的行为。

当前教学规划器支持单个静态箱体和有限条启发式候选，属于离散碰撞检查，
不是连续碰撞保证或动态避障。复杂狭窄通道需要另行接入 RRT-Connect 等规划器。

没有仿真副本时，直接保存 `robot/description/urdf/sixaxis.urdf` 会自动重新导出并刷新。
也会监听 `robot/` 下的网格、SRDF、本地转换器、导出脚本和参考场景。
有仿真副本时优先使用副本；点击「恢复内置模型」移除副本并使用内置默认 URDF。
即使内置默认 URDF 缺失，已有 `simulation.urdf` 仍可编辑、同步和构建；恢复功能需要默认 URDF 存在。
无效修改保留上次编译成功的模型并显示错误；源文件已变化时拒绝覆盖旧编辑。
刷新前暂存未提交草稿；任务运行或仿真异常时，编辑器不允许提交。
外部文件同步会刷新并复位正在运行的仿真。

### 静态网站编辑

`npm run build` 后上传 `dist/` 的全部内容即可；GitHub Pages、Nginx 等静态托管均可，
部署端不需要 Python、Node.js 或 URDF 保存接口。打开网站或 `npm run preview`，
在同一个编辑器中修改 URDF 后点击「保存并同步」：浏览器验证固定六轴结构，
用 MuJoCo WASM 重新编译，成功后保存到当前网站路径的 localStorage，再刷新场景。
几何原点、关节原点/轴/限位、力矩/速度、质量/惯量、颜色和内置网格替换均会进入物理仿真。
自动抓取方向、指垫中心与控制面板限位按新模型更新；现有拓扑与指垫标定限制仍保留。

修改仅影响当前浏览器，不会写入服务器文件，也不会影响其他访客。
重新打开同一路径会读取已保存副本；「恢复网站模型」清除副本，回到这次发布包含的模型。
清除浏览器网站数据会删除副本。需要所有访客默认看到同样修改时，
在项目中保存 URDF 后重新构建并上传 `dist/`。
无效输入不替换已保存模型；网站更新导致旧副本无法编译时，先显示网站模型，
保留旧 URDF 文本以供修正或恢复。浏览器禁止本地存储时会提示保存失败。

本机 `npm run dev` 仍保留 `simulation.urdf` 文件保存和外部文件监听。
构建时会将当前有效副本或内置模型编入静态网站；浏览器 URDF 编辑版本已单独发布到下方的新站。

## 搬运与避障

1. 复位场景，在左侧「搬运与避障」点击「红色搬运场景」。
2. 示例箱体应用成功后自动启动归位；红色方块会经绕行放到红色收纳区并回预备位。
   在「教学实验舱」查看规划日志和轨迹。自行调整箱体后，可点击上方「归位」再次运行。
3. 可修改箱体 X/Y（世界坐标，毫米）及长 X、宽 Y、高 Z 后点击「应用障碍物」。默认尺寸为 50 × 90 × 180 mm，各边可设为 10–400 mm。箱体底面保持在工作台上，显示、碰撞与避障规划同步使用新尺寸。
   支持小数毫米，不再要求 5 mm 步长；也可直接用鼠标或触屏拖动橙色箱体，X/Y 实时更新。
4. 障碍物与当前机械臂或物体过近时拒绝应用；搬运期间锁定障碍物编辑。
   目标放置区被挡住、目标不可达或跟踪超时会停止任务；调整场景或复位后重试。

位置和尺寸编辑保留 12 mm 间隙要求；重叠、间隙不足或越界时，箱体恢复上次有效位置和尺寸，
输入框和启用开关恢复为实际状态，并显示阻挡的物体/连杆及所需间隙。
任务执行和仿真异常时锁定拖动；复位保留已应用的箱体位置和尺寸，刷新网页恢复默认值。

避障在现有物理抓取任务中复用 IK，依次检查直行、抬高和侧向绕行路线。
笛卡尔插值间距 6 mm，关节碰撞采样最大间隔 0.012 rad，障碍物规划间隙为 12 mm；
执行过程中也会检查实际关节位姿到下一路点的路径。机械臂使用现有碰撞网格，腕部相机使用外壳近似，
被搬物体在规划副本中按相对夹爪变换预测；真实搬运仍靠接触力，没有 attach/weld。
该规划器目前只有一个静态箱体和有限候选路线，可能在存在其他解时仍报告「未找到安全路径」。
手动关节控制/TCP 拖拽没有自动绕行。网格使用凸包和软接触，仿真间隙不构成真机安全保证。

实现参考：[MuJoCo 几何距离和碰撞 API](https://mujoco.readthedocs.io/en/stable/APIreference/APIfunctions.html)、
[Vite 服务与热更新插件接口](https://vite.dev/guide/api-plugin.html)。

## 模型适配

- 六轴采用项目关节原点、轴、质量、惯量和限位：J1 ±2.58 rad；J2 0–3.7 rad；J3 -0.01–3.7 rad；J4–J6 ±1.57 rad。
- 原网页的 `joint7` 是界面兼容名称，对应 `gripper_joint`；两个真实仿真关节是 `gripper_joint`、`right_joint`，没有额外创建第三个夹爪关节。
- 单指 0–35 mm，总开口 0–70 mm；网页显示总开口。自动抓取使用按真实指垫中心导出的 `pinch_center` 控制点；手动 TCP 拖拽仍使用项目原有的 TCP。闭合量按物体在夹持轴上的投影宽度与指垫间隙计算，保留 0.75 mm 预压量，不再把夹爪持续压到零。
- 物理模型使用本地 `scripts/urdf_model.py` 的转换器与指垫近似，并补充两根手指的整体碰撞网格。控制器使用原模型位置作动器、重力偏置补偿与作动力限制；网页关节目标限速为 1.8 rad/s，单指目标限速为 0.05 m/s，并遵守当前 URDF 的更低速度上限。
- 初始化和复位读取本项目 `robot/zekeep.srdf` 的 `ready_pose`，避免全零姿态在启用自身碰撞后发生连杆重叠。抓取恢复该姿态的夹爪倾角，水平朝向跟随方块旋转，搬运期间保持夹持姿态；不强制垂直向下。桌面和演示点位适配本机模型，地板位于 Z=-0.06 m、桌面位于 Z=0，避免同平面渲染闪烁。
- 腕部相机是 Gemini 305 方形双目外形代理，依据[官方规格](https://www.orbbec.com/gemini-305/)使用 42 × 42 × 23 mm 外壳、18 mm 双目基线和 68° 垂直 RGB 视场角。安装位置按用户截图设置为 `link6` 局部坐标 (0, 65.5, 50) mm，未使用真实相机手眼标定。相机绕 `link6` 局部 X 轴偏转 +15°；双目外壳保留，底部腕部窗口显示左眼的一路 Three.js RGB 仿真画面；另有俯视画面，尚未计算双目深度。自动演示直接读取仿真物体位姿，未接入视觉识别模型。
- 抓取与搬运依靠 MuJoCo 接触，未使用物体 attach/weld。归位和叠放完成后，在安全撤离并等待物体稳定后回到项目 `ready_pose`，夹爪保持打开；不再面向镜头摆头或低头。
- 已启用机械臂自身碰撞，排除关系读取当前项目 SRDF，避免沿用参考机械臂的碰撞排除。MuJoCo 使用软接触及网格凸包近似，允许少量接触重叠；测试要求演示全程最大重叠小于 1.5 mm。指垫、摩擦与物体参数尚未做实物标定，不能用此网页判断真机路径安全。
- 非有限状态、关节速度超过 12 rad/s 或位置超出限位 0.08 rad 时，网页暂停仿真并要求复位；这是仿真异常保护，不是硬件急停。

网页只运行浏览器仿真，不连接 ROS、串口或真机。

## 调整收纳框与放置位置

修改 `scripts/export_model.py` 中的 `zones`，数值为世界坐标 X、Y，单位为米。
自动放置点从生成后的四条边框中心导出；修改收纳框后，归位任务会同步放到新中心。
放置高度沿用对应物体的初始中心高度。新位置需要在机械臂可达范围内。

## 调整腕部相机安装位置

修改 `scripts/export_model.py` 中的 `camera_position`，单位为米，坐标相对于
机械臂末端 `link6`，不是世界坐标。外壳、两个镜头和 RGB 视点会一起移动。
`camera_x_tilt_deg` 控制绕腕部局部 X 轴的偏转角，单位为度；
`camera_quat` 由该角度生成，顺序为 `[w, x, y, z]`。

运行 `npm run dev` 时，保存导出脚本或 `reference_models/` 场景模板后会自动
重新导出模型并刷新网页。请访问终端显示的开发地址。`npm run preview` 显示的是
`dist/` 构建结果，修改源码后需要重新执行 `npm run build` 才能更新预览。
