标定 GraspNet 参考点到真实 TCP

目标：求出一个固定三维向量，消除抓取中心与机器人 TCP 的固定几何差。

当前 J6 有低频摆动记录。J6 未稳定前，只做离线计算；禁止自动运动标定。

1. 先分清三个量

  • grasp.translation：GraspNet 抓取参考点，位于相机坐标系。
  • official_tcp：机器人模型控制点。
  • grasp.depth：GraspNet 夹爪几何参数，不是 TCP 平移补偿。

GraspNet 官方格式把 translation、rotation、depth 分开保存。不要把 depth 当 TCP 偏置。见 GraspNet 6D grasp 格式。

2. 先标真实 TCP

在工作区固定一个尖点。让夹爪定义的物理中心从至少四种明显不同姿态对准同一点。若机器人 FK 算出的 TCP 不能保持在该固定点，先修 URDF 的 official_tcp。四点法原理可参考 工业机器人 TCP 四点法。

四点法主要求 TCP 位置。TCP 轴方向仍应从 CAD、夹爪对称轴和项目的 GraspNet 轴转换确认。

3. 采集固定偏置样本

  1. 固定一个尺寸已知、边缘清楚的方块。相机、桌面、方块都不能移动。
  2. 运行视觉流程，但不自动执行。保存候选的基座坐标 p_graspnet 和旋转 R_grasp。
  3. 教师监护下低速点动。把两指真正对称地放到目标两侧；指间中心和期望抓取深度正确。
  4. 读取此时 FK 的 official_tcp 位置，记为 p_tcp_aligned。
  5. 至少采 8 组。必须改变目标位置、夹爪 yaw、20–35° 倾角；不能全是同一顶抓姿态。

4. 每组求一个局部向量

v_i = R_grasp_i.T @ (p_graspnet_i - p_tcp_aligned_i)
v   = median(v_i, axis=0)

把中位数 v 写入：

grasp_pipeline:
  grasp:
    tcp_to_grasp_center_m: [vx, vy, vz]
main.py 当前调用未传入此参数。只改 YAML 不生效；启用前必须把该值传给 grasp_to_base_poses(...)，并补回归测试。

代码使用关系：

p_tcp = p_graspnet - R_grasp @ v

5. 判断是不是固定 TCP 问题

  • v_i 在各姿态下接近，分散约 2–3 mm 内：可以使用固定偏置。
  • v_i 随腕姿变化：手眼标定、关节坐标或 RGB-D/关节同步有错。
  • v_i 随相机距离变化：深度尺度、内参或 RGB-depth 对齐有错。
  • 只有沿 approach axis 的误差变化：这是进深问题，应放进 depth_correction_m。

6. 验收

  1. 求解样本与验证样本分开；至少留 3 组未参与拟合。
  2. 离线计算最终 TCP；检查误差小于 3 mm。
  3. 先高于方块 30–50 mm 空走，确认方向和进退符号。
  4. 最后低速真抓 10 次，分别统计偏位、空抓、碰桌。
快速自测：若把夹爪旋转 180° 后，世界坐标误差也跟着旋转，多半是局部 TCP 偏置；若误差方向不变，多半是手眼或全局坐标误差。
