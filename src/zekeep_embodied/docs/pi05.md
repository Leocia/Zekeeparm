# ACT、π0.5 共用 LeRobot 训练环境

两种模型统一使用 **LeRobot 0.4.4 和 LeRobotDataset v3**。采集仍用 `collect.sh`，
ROS、遥操作和 Orbbec SDK 保持各自环境；训练和模型推理共用 `act` 环境，不再依赖 OpenPI 的 JAX 训练器或旧 v2.1 读取器。

## 环境安装

已有本项目 `act` 环境时直接复用。首次创建时按 [ACT 安装步骤](../../zekeep_act/README.md#步骤与命令)准备 Python 3.10、PyTorch 2.7.1 和 torchvision 0.22.1，CUDA wheel 与 GPU 匹配。
然后在工作区根目录安装共用模型依赖：

```bash
conda activate act
export PYTHONNOUSERSITE=1
python -m pip install -r src/zekeep_embodied/requirements-models.txt
python -m pip install -e src/zekeep_embodied
python -m pip check
export LEROBOT_PYTHON="$CONDA_PREFIX/bin/python"
./tools/pi05-model.sh doctor
```

`act.sh` 与 `run_pi05.sh` 均优先使用 `LEROBOT_PYTHON`，其次兼容 `ACT_PYTHON`，
默认 `~/miniforge3/envs/act/bin/python`。云端训练不需要 ROS。

LeRobot 0.4.4 的 π0.5 需要官方 Transformers `fix/lerobot_openpi` 分支；
`requirements-models.txt` 固定到提交 `dcddb970176382c0fcf4521b0c0e6fc15894dfe0`（Transformers 4.53.3）。
不要另装普通 Transformers 覆盖该分支，也不需要向第三方安装目录手工复制补丁。
安装时隔离用户 site-packages，避免用户目录的旧 PyAV 抢先被导入。

`doctor` 只检查依赖可导入、CUDA 是否可用、基础权重是否存在；不会分配完整模型或验证显存是否足够。

## 基础权重与语言 tokenizer

使用 LeRobot 格式的 π0.5 基础权重，默认目录 `~/.cache/zekeep/pi05_base`。
以下命令只在需要训练或模型推理的机器执行；下载需要足够磁盘空间和网络：

```bash
hf download lerobot/pi05_base --local-dir "$HOME/.cache/zekeep/pi05_base"
# 接受模型许可并登录后，预先缓存 PaliGemma tokenizer。
python -c 'from transformers import AutoTokenizer; AutoTokenizer.from_pretrained("google/paligemma-3b-pt-224")'
./tools/pi05-model.sh doctor
```

也可通过训练/预测的 `--pytorch-weight-path`、服务的 `--base-checkpoint` 指定本地基础权重目录。
模型必须完整加载所有必需参数；缺失或不匹配时直接报错，不退回随机初始化。
模型权重不随源码分发；本次迁移没有下载完整基础模型。

## 同一份 v3 数据，分别配置模型

ACT `prepare` 导出的 `dataset/train` 可以被 π0.5 直接读取，无须再次导出：

```bash
./tools/pi05-model.sh check --repo-id local/shared_v1_train --dataset-root data/demonstrations_v1/act_dataset/train
./tools/pi05-model.sh stats --repo-id local/shared_v1_train --dataset-root data/demonstrations_v1/act_dataset/train
./tools/pi05-model.sh train --repo-id local/shared_v1_train --dataset-root data/demonstrations_v1/act_dataset/train   --exp-name shared_v1_pi05 --num-train-steps 1000
```

`--dataset-root` 指向单个 v3 集合目录（含 `meta/info.json`），不是同时含 train/validation 的上层目录。
后续 `predict` 和 `serve` 继续传同一 `--dataset-root` 与 `--repo-id`。
也可以使用 `pi05-model.sh export` 单独导出选好的原始 episode，输出仍为同一种 v3 格式。
默认目录 `data/lerobot/datasets/<repo-id>`；`HF_LEROBOT_HOME` 可覆盖。

原始数据和 v3 文件中的状态、动作始终是 7 维绝对电机角度（度）；任务语言使用数据中的 `task`。
π0.5 在训练读取后执行以下模型预处理，不修改共用数据：

1. 六关节动作减去该观测时刻的状态；整个动作块使用同一个当前状态，夹爪保持绝对值。
2. 仅从训练集计算该动作表示的分位数统计，保存 `pi05_stats.json`，不会解码视频或混用验证数据。
3. 使用 LeRobot 原生 π0.5 processor 归一化、构造语言与状态 token；模型内部补到 32 维。
4. 图像由模型等比缩放补边至 224×224；缺失第三视角使用空图像及 false mask。
5. 模型输出反归一化，六关节加回当前状态，夹爪保持绝对值，向原 ROS 执行端返回 10×7 绝对角度。

统计文件绑定数据元信息与动作约定。重复统计拒绝覆盖；改变数据或配置时使用新版本目录。
采样/导出频率与现场部署的 `pi05_runtime.policy_hz` 须核对匹配；迁移不调整现场运动频率或保护参数。

## 训练方式与保存

保留本项目定制的 **VLM LoRA + Action Expert 全量微调**：
视觉编码器、多模态投影和 VLM 原权重冻结；VLM 语言层注意力/MLP 投影训练 rank 16、alpha 16 的 LoRA；
动作专家和动作输入/输出投影、时间 MLP 全量训练。不量化基础权重，batch 1，开启梯度检查点。

结果位于 `data/lerobot/checkpoints/pi05_zekeep_lora/<实验名>`，可用 `ZKEEPI_CHECKPOINTS` 覆盖。
保存 `adapter.safetensors`、原生 `config.json`、前后处理器、tokenizer、`pi05_stats.json`、
`capture_provenance.json` 和最后写入的 `finetune.json`。部署时一起复制，并保留匹配的基础权重。
加载器核对后端、数据集标识、数据元信息、统计内容及全部训练参数；部署须使用训练时的同一基础权重。
不完整目录、旧后端 adapter 或不匹配的数据会被拒绝。

训练仅在结束时保存；暂不支持周期检查点、断点恢复或基于现有 adapter 继续训练。新实验名拒绝覆盖。
验证集独立保存，目前没有自动验证集评估。显存占用、收敛与实机成功率需实际验证。

## 从旧 OpenPI 流程迁移

旧目录、原始示范、v2.1 数据和旧 adapter 均保留，程序不改写或删除它们。
新命令不会读取旧 `third_party/openpi/.venv`，也不会把 v2.1 目录改名后当作 v3。

- 有原始 episode：用共用导出器导出到新的 v3 目录，然后重新计算 π0.5 统计。
- 已有 ACT v3 数据：直接通过 `--dataset-root` 使用同一训练集及验证划分。
- 只有 v2.1 数据：先按 [LeRobot v3 迁移说明](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)转换副本，并保留来源记录。
- 旧 OpenPI `adapter.safetensors/finetune.json` 不自动迁移；使用新实验名在新后端重新训练。旧依赖仍留在磁盘，可按迁移前源码备份另行运行历史实验。

## 可选语义监督

`zekeep_embodied.jev` 是独立的低频语义路由，尚未接入实时执行循环，不直接接收相机原始数据或控制电机。
输入结构化状态须包含 `local_safety.safe`；缺失或 false 返回 stop，请求异常或低置信度返回 hold。不能替代本地安全检查。
使用时从包目录运行 `bash tools/run_pi05.sh -m zekeep_embodied.jev /路径/state.json`。
API key 放 `configs/jev.local.json` 的 `api_key` 字段或环境变量 `TYPESAFE_API_KEY`，不要写入命令参数或提交 Git；默认模型 `jev-1.13.0`。
