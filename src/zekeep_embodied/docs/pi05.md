## 数据契约

| 采集字段 | 模型语义 |
|---|---|
| `observation.images.global` | `base_0_rgb`，全局 RGB |
| `observation.images.wrist` | `left_wrist_0_rgb`，腕部 RGB |
| 无第三路相机 | 零图像，`right_wrist_0_rgb` mask 为 false |
| `observation.state` | 7 维实际电机位置，度 |
| `action` | 7 维已映射、限幅的绝对电机目标，度 |
| `task` | 原样保留的自然语言任务指令，包括中文 |

关节顺序沿用采集器：`shoulder_pan, shoulder_lift, elbow_flex, wrist_flex,
wrist_yaw, wrist_roll, gripper`。

复用官方输入输出变换：RGB 保持颜色顺序，等比缩放并补边至 224×224，
缺失视角显式屏蔽；六关节动作相对当前观测状态做差，夹爪保持绝对值。
每个 action chunk 的全部关节目标减去同一个当前状态，不是相邻动作逐步做差。
训练数据的状态/动作经过本任务的分位数归一化，再补齐至 32 维。
π0.5 同时编码语言和归一化状态，动作序列长度为 10；10 Hz 数据对应 1 秒预测窗口。
这不意味着真机应开环执行整段动作。

模型输出依次反归一化、加回当前状态、截取前 7 维，恢复为电机绝对角度。
不能重复应用主从方向映射，也不能把此输出直接接到电机而省略执行安全检查。

## 真实数据到达后

先按完整 episode 划分训练集和验证集。下面的 `/训练原始数据目录` 只包含训练 episode，
可用独立目录中的 episode 符号链接组织；不要把验证 episode 混进该目录。
同一数据集要求相机布局、安装版本、硬件标定和动作语义一致。

```bash
cd "$ZKEEP_WS/src/zekeep_embodied"

# 直接复用原始 PNG / JSONL，无需覆盖或降级已有 LeRobot v3 数据集。
JAX_PLATFORMS=cpu bash tools/run_pi05.sh -m zekeep_embodied.pi05 export /训练原始数据目录
JAX_PLATFORMS=cpu bash tools/run_pi05.sh -m zekeep_embodied.pi05 check
JAX_PLATFORMS=cpu bash tools/run_pi05.sh -m zekeep_embodied.pi05 stats
JAX_PLATFORMS=cpu bash tools/run_pi05.sh -m zekeep_embodied.pi05 check
```

首次 `check` 在没有统计文件时报告 `normalized: false`；`stats` 后应为 true。
导出目录必须不存在；中断产物保留为 `.partial`，不覆盖旧数据。
v2.1 兼容导出使用上游支持的无损 image 格式，磁盘占用高于 v3 视频；原始数据保留。
`--repo-id local/其他名称` 可用于独立验证集或后续版本。
统计命令只处理所选 repo-id；仅对训练集执行统计。

微调入口已经接好，以下命令应在资源足够的训练机器上执行：

```bash
bash tools/run_pi05.sh -m zekeep_embodied.pi05 train --exp-name pick_place_v1
```

默认是 JAX LoRA，关闭 W&B 上传，关闭 EMA，batch size 为 1，保留上游训练步数。
这个小 batch 是接入起点，不是已调优的训练配方，也不保证降低到 8 GB 可训练。
官方列出的显存门槛：推理 >8 GB、LoRA >22.5 GB、全量微调 >70 GB。
源电脑 RTX 5060 约 8 GB、内存约 16 GB；该资源信息不保证新电脑容量足够。
下载基础权重不意味着基础策略已适配 Zekeep。

## 影子模式与受监督实机验证

策略服务只监听本机 `127.0.0.1`，运行在 openpi Python 3.11 环境；ROS 运行端继续使用
`embodied` Python 3.10。先启动策略服务：

```bash
cd "$ZKEEP_WS/src/zekeep_embodied"
bash tools/run_pi05.sh -m zekeep_embodied.pi05_policy_server \
  --repo-id local/zekeep_pick_place_9hz \
  --exp-name pick_place_9hz_1000
```

策略服务启动时先完成一次 GPU 预热。另一个终端启动机械臂驱动，但不要同时启动
`zekeep_joystick` 或其他发布 `/zekeep/servo_joint_trajectory` 的节点。先运行影子模式；它读取
双相机和关节反馈，只打印模型动作，不调用使能服务、不启动伺服流、不发布运动命令：

```bash
cd "$ZKEEP_WS"
source /opt/ros/humble/setup.bash
source install/setup.bash
cd src/zekeep_embodied
conda activate embodied
export EMBODIED_PYTHON="$CONDA_PREFIX/bin/python"
bash tools/run_ros.sh -m zekeep_embodied.pi05_runtime \
  --config configs/record.yaml --shadow
```

影子输出中的 `first_action_deg` 和 `current_state_deg` 按 J1～J6、夹爪排列，单位为电机角度（度）。
限位拒绝时仍打印预测，并用 `guard_error` 标明关节名称、数值和范围；旧日志中的索引 6 指夹爪。
`action_guard_passed` 仅表示本次动作通过数值限位检查，不代表碰撞检查或其他执行条件满足。

### RViz 虚拟机械臂预测轨迹

#### 16 GB 主机推荐：先保存，再离线回放

模型服务、双相机和 RViz 同时常驻会增加内存压力。分阶段流程不改模型、标定或实机保护，
仅将一块预测保存成小文件，在回放阶段完全停止模型与相机。它不承诺修复 RViz 自身的段错误。

阶段一只启动策略服务、只读驱动和保存端，不启动 RViz：

```bash
# 终端一：策略服务。等到打印 server 后再运行保存端。
cd "$ZKEEP_WS/src/zekeep_embodied"
bash tools/run_pi05.sh -m zekeep_embodied.pi05_policy_server \
  --repo-id local/zekeep_pick_place_9hz --exp-name pick_place_9hz_1000

# 终端二：只读驱动。已运行则不要重复启动。
cd "$ZKEEP_WS"
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch zekeep_bringup driver.launch.py \
  hardware_config:=$ZKEEP_WS/src/zekeep_bringup/config/zekeep_hardware.yaml \
  auto_enable:=false

# 终端三：保存完整 10 步预测。目标文件已存在时拒绝覆盖，请换文件名。
cd "$ZKEEP_WS/src/zekeep_embodied"
bash tools/run_ros.sh -m zekeep_embodied.pi05_runtime \
  --config configs/record.yaml --shadow \
  --save-preview ../../data/pi05_prediction.json
```

保存成功后，保存端自动退出并释放相机，不再提交下一次推理。在策略服务终端按 `Ctrl+C`
释放模型；只读驱动也可停止。不要停止其他正在负责实机安全或重力补偿的节点。

阶段二仅启动 RViz 和文件回放端，不需要模型服务、驱动、相机或手柄：

```bash
# 终端一：RViz
cd "$ZKEEP_WS"
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch src/zekeep_embodied/tools/pi05_preview.launch.py

# 终端二：离线回放
cd "$ZKEEP_WS/src/zekeep_embodied"
bash tools/run_ros.sh -m zekeep_embodied.pi05_preview \
  ../../data/pi05_prediction.json
```

回放端等 RViz 订阅后发送一次，播放完停住；需再次播放可重启回放端。文件回放不会检查
或连接 8000 端口，也不会启用相机或 GPU。旧的 `--preview` 与 `--preview-once` 实时入口保持可用。

文件格式为 `schema_version: 1`、`kind: zekeep_pi05_preview` 的 JSON，包含模型标识、
完整 `state_deg` / `actions_deg`、`guard_report` 和标准 `display_trajectory` 消息。
轨迹已按采集时标定转换为 ROS 手臂角度（rad）与夹指行程（m），离线端不会用新的标定重新解释。
损坏的关节顺序、点数、非有限位置或非递增时间戳会拒绝回放；限位拒绝的原始预测仍可保存和
查看，但不意味着安全可执行。这里只回放预测运动学，不能仿真抓取成功率或物体动力学。

#### 实时预览（内存允许时）

保留策略服务和只读驱动，停止旧影子进程。另一个终端启动独立预览窗口：

```bash
cd "$ZKEEP_WS"
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 launch src/zekeep_embodied/tools/pi05_preview.launch.py
```

重新启动影子端，增加 `--preview`：

```bash
cd "$ZKEEP_WS/src/zekeep_embodied"
bash tools/run_ros.sh -m zekeep_embodied.pi05_runtime \
  --config configs/record.yaml --shadow --preview
```

窗口显示观测起始姿态和蓝色预测机械臂，按 9 Hz 时间间隔播放完整未来 10 步（约 1.11 s），
并显示轨迹残影。RViz 的轨迹滑块支持暂停和逐步检查；`Show Trail` 可关闭残影。
动画完成当前块再切换到最新预测，避免约 2 Hz 的推理结果不断截断播放。
由于真实机械臂没有移动，各块从真实起始姿态重新播放；模型输出变化时会看到跳动。
需要稳定检查时，将 `--preview` 替换成 `--preview-once`：等待 RViz 订阅后只发送一次预测，
播放完停住。再次运行影子端可刷新快照。窗口默认不循环播放；需要回放时使用轨迹滑块面板。
预览使用固定约 0.111111 s 的帧间隔，而非 Humble 插件的实时倍率索引路径。

这是原始预测的运动学预览，不是控制指令，也不是闭环任务仿真。每个块从本次推理的真实观测
开始，不把虚拟姿态冒充下一次相机观测。预览不会把手臂动作截为每步 0.5°，也不会隐藏越界
预测；夹爪仅使用驱动的电机角度到指尖行程映射作显示。限位拒绝仍能预览，不表示可执行。
预览仅发布 `/pi05_preview/state` 和 `/pi05_preview/trajectory` 的 MoveIt 显示消息，不启动
驱动、控制器或 MoveIt 执行服务，不发布实机指令或共享 TF。显示原点使用独立的
`/pi05_preview/tf_static`，不会覆盖实机坐标系。

实现采用官方 [DisplayTrajectory](https://github.com/moveit/moveit_msgs/blob/ros2/msg/DisplayTrajectory.msg)
契约和 Humble 的 [轨迹显示插件](https://github.com/moveit/moveit2/blob/humble/moveit_ros/visualization/rviz_plugin_render_tools/src/trajectory_visualization.cpp)。

确认图像、反馈、推理延迟和预测方向后，清空工作区并准备硬急停。手动使能机械臂，再启动执行模式：

```bash
ros2 service call /zekeep/enable std_srvs/srv/Trigger '{}'
bash tools/run_ros.sh -m zekeep_embodied.pi05_runtime \
  --config configs/record.yaml --execute
```

执行模式要求交互输入 `MOVE`，并要求先松开再按住配置的 deadman。松开 deadman、反馈过期、
推理超过时限、相机不同步、非有限动作、错误模型或关节越界都会停止伺服流。每次只采用动作块
第一步，单次关节变化默认不超过 `0.5°`，速度不超过 `0.10 rad/s`。夹爪动作先停止手臂伺服，
完成后必须松开并重新按下 deadman。运行端不会自动使能电机。

该入口仍不提供环境碰撞或自碰撞检查。首次仅在清空的工作区低速测试，操作者必须保持急停可用。
